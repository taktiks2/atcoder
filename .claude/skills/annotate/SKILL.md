# annotate

AC 済みのコードに `// algo:` タグ・考察コメント・`// alt:` ブロックを付ける。規約の唯一の権威は `TAGS.md`。

## 必ず守ること

**AC コード本体を 1 文字も変えない。** 追加するのはコメントだけ。

- `Write` で全文置換しない。**コメントの挿入を `Edit` で行う**。ロジックが同じである保証は diff だけ
- 「ついでにここを綺麗に」は別の依頼。やらない
- 本体を変えたくなったら、それは `// alt:` に書く

**書き込み前に diff を見せて確認を取る。** 対象は 2 つとも:

- `*/src/bin/<問題>.rs`
- `TAGS.md` — 語彙の追加は repo 全体の検索性に効く。無断で増やさない

**一時ファイルをパッケージ内に作らない。** `src/bin/` に置いた `.rs` は `Cargo.toml` の bin 定義と食い違い `just test` を壊す。alt の動作確認はスクラッチパッドで行う。

## 手順

1. 対象ファイルを読む。問題文は WebFetch で取り、**制約の実物**を確認する（コメントに書く数値の根拠になる）
2. 文体の基準を合わせる: `abc/abc212/src/bin/c.rs`（厚め）/ `abc/abc196/src/bin/c.rs`（標準）
3. タグを選び、`TAGS.md` と照合する（下記）
4. 考察コメントを main の前に書く
5. `// alt:` を main の後ろ（ファイル末尾）に書く
6. **diff を見せて確認を取る** → 書き込み
7. `just test <contest> <problem>` で AC のままか確認する

## タグの照合（必須）

`TAGS.md` の表は **3 列目が「使ってはいけない表記」**。選んだタグがそこに載っていたら正規表記に直す。

| 確認 | 方法 |
| --- | --- |
| 語彙にあるか | `grep -n '<tag>' TAGS.md` |
| 使わない表記でないか | ヒットした行の 3 列目を見る |
| 既存の使用例 | `just algo <tag>` |

語彙に無い新タグは、**`TAGS.md` への追記をユーザーに提案してから**使う。追記先は該当カテゴリの表。

既知のドリフト: `cumulative-sum`（正: `prefix-sum`）、`sorting`（正: `sort`）を含む 13 タグが語彙外のまま使われている。**新規に増やさない。** 遭遇したら報告するだけにし、一括修正は別依頼として扱う。

## 書く内容

**考察コメント（main の前）** — 「何をしたか」ではなく**なぜそれで正しいか**を書く。

- 素朴な解法がなぜ落ちるか（計算量を具体的な数字で）
- 選んだ解法が正しい理由
- 型の理由（オーバーフローする具体的な値。例: `8*10^10` は i32 の `2.1*10^9` を超える）
- 踏みやすい落とし穴。特に「サンプルは通るのに WA」になる形

**`// alt:`（ファイル末尾）**

- 1 行目に**何がどう良いか**を必ず書く（観点: Rust らしさ / 計算量 / 短さ）。「より良い解法」だけでは後から学びが分からない
- 1 別解 = 1 ブロック。コードは `// ` でコメントアウトして並べる
- 2〜3 本まで。多いと読まれない
- **動くことを確認してから載せる**（確認はスクラッチパッドの一時パッケージで）
- 「絶対に動く形で残したい」ものはコメントではなく `#[allow(dead_code)]` 関数にする

## Red flags — 手を止める

- `Write` で `src/bin/*.rs` を全文置換しようとしている
- diff を見せずに書き込もうとしている
- `TAGS.md` に無断で行を足そうとしている
- `src/bin/` に一時ファイルを作ろうとしている
- AC コード本体の式や変数名を「ついでに」変えている

| 言い訳 | 現実 |
| --- | --- |
| 「ロジックは同じだから全文置換でいい」 | 同じである保証は diff だけ。Edit でコメントを挿入する |
| 「依頼が明示的だったから確認は不要」 | 依頼はコメント付与。TAGS.md の語彙変更と本体書き換えは含まれない |
| 「一時ファイルは後で消すから平気」 | 消し忘れると `just test` が壊れる。スクラッチパッドに置く |
| 「このタグの方が自然だ」 | 自然さより検索性。`TAGS.md` の正規表記に従う |
| 「新しいタグを足した方が正確だ」 | 語彙が増えるほど検索が分散する。既存で表せないか先に確認する |

## 完了報告

付けたタグ / alt の本数 / `just test` の結果を 1 行ずつ。`TAGS.md` を変更したならその旨も。
